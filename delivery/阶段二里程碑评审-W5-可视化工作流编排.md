## 2. 表结构设计

新增 5 张租户隔离的表，`CREATE TABLE IF NOT EXISTS`，CASCADE 级联删除：

| 表名 | 用途 | 关键字段 |
|------|------|----------|
| `workflow_definition` | 工作流定义（draft/active/archived） | name, status, created_by |
| `workflow_node` | 节点（tool/condition/input/output） | node_type, tool_type, position, config, retries, timeout |
| `workflow_edge` | 有向边（含可选布尔条件表达式） | from_node_id, to_node_id, condition |
| `workflow_run` | 执行记录 | status, inputs, outputs, triggered_by, triggered_by_type |
| `workflow_run_log` | 节点级执行日志 | node_id, status, input, output, retry_count |

**关键约束**：
- `UNIQUE(workflow_definition: tenant_id, name)` — 同名工作流保护
- `UNIQUE(workflow_edge: workflow_id, from_node_id, to_node_id)` — 同对节点只一条边
- `is_sandbox` 标识沙箱租户

## 3. 引擎能力

### 3.1 DAG 执行模型
- **Kahn 拓扑排序**：启动前检测环，非法图拒绝执行
- **并行节点执行**：每轮找出所有「前置已全部满足」的节点，`Promise.allSettled` 并行
- **条件分支**：边条件 `Function('result', 'return ' + condition)` 求值，控制下游节点激活
- **重试机制**：按 `node.retries + 1` 次尝试，失败后自动重试
- **超时防护**：执行前检查 + 执行后检查双重超时，防止慢工具绕过 timeout
- **死锁处理**：所有条件分支都不通过时，剩余节点标记 cancelled

### 3.2 工具注册表
- `registerTool(name, executor)` — 插件式工具注册
- `getRegisteredTools()` — 查询已注册工具列表
- 内置测试工具：`test:greet` / `test:double` / `test:slow` / `test:counter`

### 3.3 错误处理
- 未注册工具 → 节点失败
- 非 active 状态工作流 → 拒绝执行
- 条件求值异常 → 返回 false，保守处理

## 4. 关键 Bug 修复记录

### Bug #1: 条件表达式求值始终返回 undefined
**根因**：`new Function('result', 'result.result >= 10')` 创建的是**语句体函数**，表达式求值了但没有 `return`，返回 `undefined`，`Boolean(undefined)` = `false`，导致所有条件分支永远走不到。

**修复**：`new Function('result', 'return ' + condition)` — 用 `return` 包裹条件表达式。

**影响**：这是整个条件分支功能的致命缺陷，修复后 47 个测试全部通过。

### Bug #2: Input 节点输出缺少 input_received 标识
**根因**：input 节点的初始输出只包含 `{ ...initialInputs, _input_node: true }`，缺少 `input_received: true`。

**修复**：初始输出改为 `{ input_received: true, ...initialInputs, _input_node: true }`。
