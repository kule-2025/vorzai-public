## 三、过程中修复的测试隐患（非 M3 代码回归）

阶段评审期发现 `data-integrity.test.ts` 偶发 `500 UNIQUE constraint failed: tenants.slug`：

- **根因**：`test-helpers.createTenant` 固定发送 `tenantName: '测试租户'`，而 `authService` 用 `tenantName` 派生全局唯一的 `tenants.slug`；该 suite 第 3 个 `describe` 块的 `beforeAll` 漏写 `removeDbFiles`，复用测试库时继承了上一轮残留的租户 slug → 冲突。
- **修复**（两处，最小化且对其它 suite 更健壮）：
  1. `createTenant` 改为带随机后缀的 `测试租户_${rand}` → slug 全局唯一，任何复用库都不会撞名；
  2. data-integrity 第 3 块 `beforeAll` 补 `removeDbFiles(TEST_DB_PATH)`，与其余块一致。
- 修复后该 suite 稳定通过，全量 242/242 达成。

> 注：本沙箱对 shell `rm` / PowerShell `Remove-Item` 启用 safe-delete 拦截，但 Node `fs.unlinkSync` 在测试进程内可正常工作，故测试库清理逻辑本身不受影响；偶发失败纯属用例层面的 slug 唯一性问题。
