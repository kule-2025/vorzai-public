## 1. 业务背景与价值

### 1.1 业务背景

- **当前业务现状（行业 / 产品 / 用户规模）**
  - 行业：面向电商业务场景，覆盖四类电商形态——新媒体/直播电商、跨境电商、传统电商、线上线下融合（O2O）。
  - 产品：Vorzai 电商 Agent v0.1.0，基于现有 Electron + React + TypeScript 桌面级 AI Agent（本地优先、离线可用），已有底座含多租户权限引擎（RBAC+ABAC）、多模型适配工厂（LLMAdapterFactory）、业务链（订单/库存/结算）、HRMS（OGSM/RACI/激励/试点）、连接器注册表、事件总线 moduleBus、文件 IO。
  - 用户规模：电商企业组织内多类角色——电商业务负责人/HRD（甲方决策者）、电商运营与客服一线（最终用户A）、HR 与中层管理者（最终用户B）；本期 MVP 为桌面本地优先、单租户为主（客户端模拟隔离），完整版引入轻量自建后端实现服务端强隔离。
- **触发本次需求的事件（新场景 / 痛点修复）**
  - 业务链闭环断裂：现有 business-chain 仅覆盖订单/库存/结算 3 环节，"组盘""客服"无业务模型（material_digest G1）。
  - 对话式工作流仅 UI 壳：Dashboard"智能助手输入框"handleSend 仅 console.log，无对话引擎/多轮/工具调用（material_digest G2）。
  - 企业知识库与企业专属 Skill 缺失：skill-center.getKnowledgeLinks 返回静态字符串列表（material_digest G3）。
  - email 连接器缺失：ConnectorType 枚举无 email（material_digest G4）。
  - HR 真实计算缺失：hr-system 员工/考勤/绩效/薪酬均为内存 mock（material_digest G6）。
  - 多租户隔离不达标：客户端模拟（mtStore 命名空间）、HMAC 默认硬编码密钥（material_digest G8，R-03）。
- **本系统在产品矩阵中的位置**
  - 在现有 Vorzai 底座上，从"HRMS 内核 + 业务链骨架"演进为"HR 管理 + 电商业务方案专家"双定位桌面系统，将立项→选品→组盘→订单→客服五环节业务链与 OGSM 人力目标贯通。能力在桌面应用内闭环消费，无独立下游系统。

## 5. 用户旅程（UserStory）

> 每条 UserStory 按 7 段式展开：业务场景 / 业务流程 / UE 原型 / 业务逻辑 / 数据描述 / 验收标准 / 外部集成接口。验收标准使用 Given/When/Then，含正常路径与异常路径。

### 5.1 US-1 对话式工作流引擎（F1 对话引擎骨架；F2 多轮上下文为完整版扩展）

#### 5.1.1 业务场景

- **视角**：最终用户A（电商运营/客服一线）
- **描述逻辑**：用户在对话式工作台输入框输入一句自然语言（如"帮我把 A、B 组个直播套餐"或"查一下客户 123 的订单"），系统在首字 ≤3s 内开始响应，识别意图并调用对应业务工具（组盘/客服/选品/定价/OGSM 等），以对话驱动完成 ≥5 类高频操作，减少多系统切换。完整版支持跨轮上下文（F2）连续多步任务。

#### 5.1.2 业务流程

- **视角**：用户
- **描述方式**（Given / When / Then）：
  - **正常路径**：Given 用户已登录且 LLM 适配器已配置，When 用户在输入框输入"把 A、B 组个直播套餐"并回车，Then 系统在 P99≤3s 内返回首字，识别为"组盘"意图，展示工具调用状态，并生成半自动填充的组盘表单供确认提交。
  - **多轮（完整版 F2）**：Given 上一轮已完成库存查询，When 用户说"用刚才的结果组盘"，Then 引擎从跨轮上下文取 slot 值继续组盘流程。
  - **异常路径**：Given LLM 服务未配置或超时，When 用户发送消息，Then 系统提示"对话引擎暂不可用，请检查模型配置"并保留输入内容，不丢失。

#### 5.1.3 UE 原型

- 核心路径：智能助手主页（WorkBuddy 风格输入框 + 业务标签选择器 + Enter 发送）→ 对话任务浮层（工具调用状态展示/一键插入结果）→ 对应业务工作台（组盘/客服表单半自动填充）。
- 交互约束：输入到首字 P99≤3s；核心组盘/客服路径 ≤5 步（对话驱动）。

```mermaid
flowchart LR
    A[用户输入自然语言] --> B[意图识别/分类]
    B --> C{命中业务工具?}
    C -->|是| D[工具调用骨架 CALM式]
    C -->|否| E[通用问答/RAG检索]
    D --> F[半自动填充业务表单]
    F --> G[用户确认提交]
    G --> H[业务模块更新+审计]
```

#### 5.1.4 业务逻辑

- **视角**：业务系统
- **描述方式**：对话引擎（重构自 agent-hub，复用 llm-platform 适配器工厂）→ 意图识别模块 → 工具调用调度（组盘/客服/选品/定价/OGSM 工具，经 moduleBus 调用业务链/HRMS/知识库）→ 结果回填对话。MVP 为单轮 + 工具调用骨架（CALM 式，LLM 理解 + 确定性 Flow 执行）；完整版追加跨轮上下文状态追踪（tracker store 落 IndexedDB）。所有关键操作写审计日志（F14）。

#### 5.1.5 数据描述

- 输入：用户自然语言文本、当前业务标签、租户上下文（TenantID/UserID，经 HMAC 注入）。
- 流转：意图识别结果（intent + slots）→ 工具调用请求/响应（经 moduleBus）→ 业务数据写回（mtStore/IndexedDB）→ 对话历史（IndexedDB，完整版跨轮）。
- 输出：流式对话文本、工具调用状态事件、业务操作结果。

#### 5.1.6 验收标准 AC

- **正常路径**：
  - Given 已配置 LLM 且用户登录，When 输入"把 A、B 组个直播套餐"，Then 系统按延迟基线返回首字（P50≤800ms / P90≤1.5s / P99≤3s，待上线实测校准，见 §6.2），识别组盘意图并展示工具调用状态，生成可编辑组盘表单。
  - Given 对话引擎可用，When 用户连续发起组盘/客服/选品/定价/OGSM 任一类操作，Then 系统对每类均能驱动对应工具完成，累计覆盖 ≥5 类高频操作（N3）。
- **异常路径**：
  - Given LLM 未配置或返回超时（>60s AbortController），When 用户发送消息，Then 系统提示不可用并保留输入框内容，不抛出未捕获异常。
  - Given 意图无法识别（置信度低于阈值），When 用户发送模糊指令，Then 系统追问澄清或提供候选业务标签，不静默失败。
  - Given 用户无对应工具调用权限（ABAC 拒绝），When 触发受限操作，Then 系统拒绝执行并提示权限不足，同时写安全审计事件。

#### 5.1.7 外部集成接口

- 依赖 LLM 服务（OpenAI/DeepSeek/通义/Ollama 等），经 llm-platform 适配器工厂，HTTPS 流式接入（同步）。
- 工具调用经 moduleBus 调用业务链/HRMS/知识库（进程内）。无外部 SaaS 依赖（O3）。

### 5.2 US-2 企业知识库上传与检索（F3）

#### 5.2.1 业务场景

- **视角**：最终用户B / 一线
- **描述逻辑**：用户将企业 SOP、选品手册、客服话术等文档上传至本地知识库，系统解析（json/csv/xlsx/pdf/txt/md 等）、分片、向量化（本地向量库 IndexedDB），后续对话可检索增强（RAG），提升对话与知识命中率。

#### 5.2.2 业务流程

- **视角**：用户
- **描述方式**（Given / When / Then）：
  - **正常路径**：Given 用户进入知识库管理页，When 上传一份 PDF 选品手册并点击"入库"，Then 系统在解析完成后将其切分向量化，提示"入库成功，可检索"，并在对话中可被检索增强。
  - **异常路径**：Given 上传文件类型不支持或超 5MB 分片限制，When 用户拖入 exe 文件，Then 系统拒绝并提示"不支持的文件类型/超限"，不写入。

#### 5.2.3 UE 原型

- 知识库管理页：上传区（拖拽/选择）→ 解析进度 → 文档列表（名称/类型/分片数/状态）→ 检索测试框。
- 对话中：知识检索结果以引用片段形式展示。

#### 5.2.4 业务逻辑

- **视角**：业务系统
- 文档经 file-io 解析（SupportedFormat 含 pdf/xlsx/csv/txt/md/json/xml/yaml）→ 分片（5MB 分片 + SHA256）→ 本地向量化（IndexedDB 向量库）→ 检索（混合/重排，参考 Dify 管道自研）→ 注入对话上下文（RAG）。MVP 本地向量库，完整版自托管向量库 + 企业库（F3 扩展）。

#### 5.2.5 数据描述

- 输入：文档文件（多格式）、租户上下文。
- 流转：fileParser 解析 → 分片+SHA256 → 向量化 → IndexedDB 向量表 → 检索请求/命中片段 → 对话上下文注入。
- 输出：可检索知识文档、检索命中片段（含来源引用）。

#### 5.2.6 验收标准 AC

- **正常路径**：
  - Given 用户上传支持的 PDF/CSV 文档，When 点击入库，Then 系统在 P95≤2s 内（待上线实测校准，见 §6.2）完成解析向量化并返回成功，文档出现在可检索列表。
  - Given 已入库含"直播套餐毛利"的文档，When 对话问"直播套餐毛利怎么算"，Then 检索返回相关片段并作为引用注入回答。
- **异常路径**：
  - Given 上传不支持的扩展名或超大文件，When 触发入库，Then 系统拒绝并给出明确错误，不落库。
  - Given 向量化失败（OOM/解析异常），When 入库中断，Then 系统回滚部分分片并提示重试，不残留脏数据。

#### 5.2.7 外部集成接口

- 复用 file-io 模块（进程内）；向量库本地（IndexedDB），无外部依赖。完整版可选自托管向量库（pgvector/Qdrant）经后端（F15）。

### 5.3 US-3 企业专属 Skill 创建（F4；F17 Skill 市场为完整版）

#### 5.3.1 业务场景

- **视角**：最终用户A/B
- **描述逻辑**：用户将重复性工作（如"每周竞品价格监控""直播话术生成"）固化为企业专属 Skill：编写 SOP 指令 + 绑定工具（如定价工具、知识检索），打包为可复用能力，在对话中一键调用。完整版支持 Skill 市场跨团队/企业发布复用（F17）。

#### 5.3.2 业务流程

- **视角**：用户
- **描述方式**（Given / When / Then）：
  - **正常路径**：Given 用户在 Skill 编辑页，When 填写"竞品价格监控"SOP 并绑定"动态定价"工具后保存，Then 系统生成 Skill 卡片，对话中输入"运行竞品价格监控"即可触发。
  - **异常路径**：Given 绑定的工具已被删除，When 用户运行该 Skill，Then 系统提示"工具缺失，Skill 不可用"并建议重新绑定。

#### 5.3.3 UE 原型

- Skill 编辑页：基本信息（名称/描述）→ SOP 指令编辑 → 工具绑定树（复用 AgentConfig 左树右编辑布局）→ 保存/测试。
- 个人工作台"我的 Skill"管理区。

#### 5.3.4 业务逻辑

- **视角**：业务系统
- Skill 结构（参考 Dify .skill/SKILL.md 自研，不复制）：指令 + 参考 + 工具绑定。保存至 skill-center（重构自静态列表为可创建/存储），经 moduleBus 在对话引擎中可调。MVP 基础版（静态 SOP + 工具绑定），完整版动态生成 + 市场（F17）。

#### 5.3.5 数据描述

- 输入：Skill 名称、SOP 文本、绑定工具 ID 列表、租户上下文。
- 流转：Skill 定义存 IndexedDB → 对话引擎加载可用 Skill → 触发时执行 SOP + 工具 → 结果回填。
- 输出：可复用 Skill 实例、执行结果。

#### 5.3.6 验收标准 AC

- **正常路径**：
  - Given 用户创建并保存一个绑定"动态定价"工具的 Skill，When 对话中输入该 Skill 触发词，Then 系统执行 SOP 并调用绑定工具返回结果。
  - Given MVP 范围，When 用户创建 ≥1 条 SOP Skill，Then 系统记录并可在"我的 Skill"管理（对齐 V4 自建 Skill ≥1 条）。
- **异常路径**：
  - Given Skill 绑定的工具被移除，When 运行，Then 系统提示工具缺失并建议修复，不静默报错。
  - Given Skill 名称重复，When 保存，Then 系统提示重名并阻止覆盖（或提示版本化）。

#### 5.3.7 外部集成接口

- 复用 skill-center / moduleBus（进程内）。完整版 Skill 市场（F17）依赖服务端强隔离（F15/O5）。

### 5.4 US-4 OGSM 目标分解与仪表盘（F5 + F6 RACI+激励+试点）

#### 5.4.1 业务场景

- **视角**：甲方决策者 / 最终用户B
- **描述逻辑**：决策者将公司目标按 OGSM 四层（目标→目的→策略→衡量）分解，配置责任人矩阵（RACI）、激励计算与灰度试点；系统提供完成率/对齐率仪表盘，闭环追踪到人，支持每周复盘调整。

#### 5.4.2 业务流程

- **视角**：用户
- **描述方式**（Given / When / Then）：
  - **正常路径**：Given 决策者进入 OGSM 目标树，When 新增一个 Objective 并分解出 Goal/Strategy/Measure 并指定责任人，Then 系统构建四层树并在仪表盘显示完成率/对齐率。
  - **异常路径**：Given 目标权重之和 ≠100% 或责任人冲突，When 保存，Then 系统提示权重/冲突并阻止（RACI 冲突检测）。

#### 5.4.3 UE 原型

- OGSM 目标树（拖拽/折叠/权重设置）、完成率仪表盘（多维下钻）、RACI 矩阵（角色分配/冲突检测）、激励与试点页。

#### 5.4.4 业务逻辑

- **视角**：业务系统
- 复用 hr-system/hrms（OGSM/RACI/激励/试点），扩展仪表盘指标（完成率 = 已完成 Measure/总 Measure；对齐率 = 有责任人 Measure/总 Measure）。业务链/订单/客服完结经反馈回路 T+1 离线统计回填完成率（参考飞书 OKR 四阶段闭环理念自研）。

#### 5.4.5 数据描述

- 输入：OGSM 四层节点、权重、RACI 角色、激励规则、试点阶段。
- 流转：hrStore（IndexedDB）持久化 → 仪表盘聚合计算 → 反馈回路（订单/客服完结事件经 moduleBus）→ T+1 完成率更新。
- 输出：OGSM 树、完成率/对齐率、RACI 矩阵、激励计算结果。

#### 5.4.6 验收标准 AC

- **正常路径**：
  - Given 决策者分解 OGSM 四层并指定责任人，When 保存，Then 系统在目标树与仪表盘正确展示完成率/对齐率，且对齐率随责任人分配更新。
  - Given 订单/客服环节完结，When T+1 统计触发，Then 相关 OGSM Measure 完成率相应更新。
- **异常路径**：
  - Given 子节点权重和 ≠100%，When 保存，Then 系统提示并阻止保存，保持数据一致。
  - Given 同一 Measure 分配两个 Responsible，When 保存 RACI，Then 系统标记冲突并提示去重。

#### 5.4.7 外部集成接口

- 复用 hrms/hr-system、moduleBus（进程内）。无外部依赖。

### 5.5 US-5 业务链-组盘建模（F7）

#### 5.5.1 业务场景

- **视角**：最终用户A（运营）
- **描述逻辑**：运营在组盘工作台为直播/跨境等场景创建商品组合（组盘），系统计算组合毛利、预占库存，并打通至订单/库存主链路。MVP 为组盘骨架（商品组合/毛利/库存预占模型）。

#### 5.5.2 业务流程

- **视角**：用户
- **描述方式**（Given / When / Then）：
  - **正常路径**：Given 运营在组盘工作台选择商品 A、B 并设置套餐价，When 点击"计算并保存"，Then 系统计算组合毛利与库存预占，生成组盘记录并提示成功。
  - **异常路径**：Given 所选商品库存不足以预占，When 保存，Then 系统提示"库存不足"并高亮缺口，不生成组盘。

#### 5.5.3 UE 原型

- 组盘工作台：商品选择器 → 套餐价/毛利实时计算 → 库存预占校验 → 提交。可由对话驱动（US-1）半自动填充。

#### 5.5.4 业务逻辑

- **视角**：业务系统
- 新建组盘模型（business-chain 扩展）：组合定义（SKU 列表/数量）、毛利计算（套餐价 - Σ成本）、库存预占（allocateInventory 扩展）。经 moduleBus 与订单/库存模块协作，主链路贯通（立项→选品→组盘→订单→客服）。

#### 5.5.5 数据描述

- 输入：SKU 列表、数量、套餐价、成本基准、租户上下文。
- 流转：组盘定义存 IndexedDB → 毛利计算 → 库存预占校验/占用 → 主链路事件（moduleBus）→ 订单/库存更新。
- 输出：组盘记录、毛利、预占库存量。

#### 5.5.6 验收标准 AC

- **正常路径**：
  - Given 运营选 2 个有足库存商品并设套餐价，When 保存，Then 系统在 P95≤1.5s 内（待上线实测校准，见 §6.2）计算毛利并预占库存，生成组盘且可在订单环节引用。
  - Given 组盘经对话发起（US-1），When 引擎填充表单，Then 用户确认后走同一保存逻辑。
- **异常路径**：
  - Given 某 SKU 库存小于预占量，When 保存，Then 系统提示库存不足并阻止，预占不生效。
  - Given 套餐价低于成本导致负毛利，When 保存，Then 系统提示负毛利预警（可强制继续或取消）。

#### 5.5.7 外部集成接口

- 复用 business-chain / moduleBus（进程内）。完整版真实库存经平台 API（F16/O1）。

### 5.6 US-6 业务链-客服 Agent 工作流（F8）

#### 5.6.1 业务场景

- **视角**：最终用户A（客服）/ 受影响方终端客户
- **描述逻辑**：客服通过对话或客服工作台处理客户咨询：系统先检索知识库/订单自动应答，无法解决时生成工单并支持转人工，保障客服问题解决时效（影响终端客户体验）。

#### 5.6.2 业务流程

- **视角**：用户
- **描述方式**（Given / When / Then）：
  - **正常路径**：Given 客户问"订单 123 何时发货"，When 客服在客服工作台检索，Then 系统返回订单状态并自动生成应答草稿，客服一键发送。
  - **转人工**：Given 问题超出知识库/规则，When 客服点"转人工"，Then 系统创建人工工单并指派责任人，状态可跟踪。
  - **异常路径**：Given 订单号不存在，When 检索，Then 系统提示"未找到订单"并建议核对，不返回错误数据。

#### 5.6.3 UE 原型

- 客服工作台：问答框（对话驱动）→ 知识/订单检索结果 → 工单创建/状态跟踪 → 转人工按钮。

#### 5.6.4 业务逻辑

- **视角**：业务系统
- 客服 Agent 工作流（重构自 AgentType.customer-service + RightPanel 卡片）：问答（RAG/订单检索）→ 工单（状态机：新建/处理中/已解决）→ 转人工（生成 RACI 责任人工单）。经 moduleBus 与知识库/业务链协作，关键操作写审计（F14）。

#### 5.6.5 数据描述

- 输入：客户问题、订单号/客户标识、租户上下文。
- 流转：意图识别 → 知识库/订单检索 → 应答草稿 → 工单状态机 → 转人工指派 → 审计日志。
- 输出：应答文本、工单、转人工记录。

#### 5.6.6 验收标准 AC

- **正常路径**：
  - Given 有效订单号咨询，When 客服检索，Then 系统返回准确订单状态（业务提交 P95≤1.5s，待上线实测校准，见 §6.2）并生成可发送应答。
  - Given 问题无法自动解决，When 点转人工，Then 系统创建工单并指派责任人，状态可见。
- **异常路径**：
  - Given 订单号不存在/无权限，When 检索，Then 系统提示未找到/无权限，不返回脏数据。
  - Given 知识库无相关条目且未转人工，When 客户追问，Then 系统提示"建议转人工"不编造答案。

#### 5.6.7 外部集成接口

- 复用知识库（US-2）/ business-chain（US-7）/ moduleBus（进程内）。可选 email 连接器（US-8/F11）发送客户通知。

### 5.7 US-7 业务链-订单/库存/结算主链路（F9）

#### 5.7.1 业务场景

- **视角**：最终用户A（运营）
- **描述逻辑**：复用现有 business-chain（订单/库存/结算），打通立项→选品→组盘→订单→客服主链路，使组盘结果可生成订单、库存预占/扣减、结算记录贯通，形成业务闭环。

#### 5.7.2 业务流程

- **视角**：用户
- **描述方式**（Given / When / Then）：
  - **正常路径**：Given 组盘已生成且库存充足，When 运营基于组盘创建订单，Then 系统扣减库存、生成结算记录，主链路状态在仪表盘可见。
  - **异常路径**：Given 库存不足，When 创建订单，Then 系统拦截并提示库存缺口，不生成负库存订单。

#### 5.7.3 UE 原型

- 业务链视图：选品→采购→库存→营销→订单→履约→售后节点；订单/库存/结算状态看板。

#### 5.7.4 业务逻辑

- **视角**：业务系统
- 复用 business-chain（OrderChain/InventorySnapshot/SettlementRecord），扩展与组盘（US-5）、客服（US-6）的贯通：updateOrderStatus / allocateInventory / reconcileSettlement 经 moduleBus 协同，主链路事件驱动 OGSM 反馈回路（US-4）。

#### 5.7.5 数据描述

- 输入：组盘引用、下单量、租户上下文。
- 流转：组盘→订单创建→库存扣减/预占→结算记录→主链路事件（moduleBus）→ OGSM 完成率反馈。
- 输出：订单、库存快照、结算记录。

#### 5.7.6 验收标准 AC

- **正常路径**：
  - Given 组盘有效且库存足，When 创建订单，Then 库存扣减、结算生成、主链路贯通（业务提交 P95≤1.5s，待上线实测校准，见 §6.2），OGSM 相关 Measure 完成率更新。
  - Given 客服工单完结，When 触发反馈，Then 对应业务指标回流仪表盘。
- **异常路径**：
  - Given 库存不足，When 下单，Then 系统拦截并提示，不产生负库存。
  - Given 结算金额异常（超出阈值），When 对账，Then 系统标记异常并写审计，不静默通过。

#### 5.7.7 外部集成接口

- 复用 business-chain / moduleBus（进程内）。完整版真实平台订单/库存经 API（F16/O1）。

### 5.8 US-8 账号权限体系与 email 连接器（F10 + F11）

#### 5.8.1 业务场景

- **视角**：甲方决策者 / 管理员 / 最终用户A/B
- **描述逻辑**：管理员对标钉钉配置账号体系（RBAC+ABAC 角色 + 委托权限点），并为用户分配角色/委托权限；系统补 email 连接器类型，支持基础邮件收发，使通知/协同可通过邮件触达。

#### 5.8.2 业务流程

- **视角**：用户
- **描述方式**（Given / When / Then）：
  - **正常路径（权限）**：Given 管理员在权限面板新建员工并分配"运营"角色 + 委托"客服:read"权限，When 保存，Then RBAC+ABAC 生效，该员工仅能访问授权范围。
  - **正常路径（email）**：Given 已配置 SMTP/IMAP，When 用户点"发送测试邮件"，Then 系统经 email 连接器收发成功并提示。
  - **异常路径**：Given HMAC 密钥为默认硬编码，When 系统启动，Then 告警提示密钥未配置并建议设置 VORZAI_MT_HMAC_SECRET（不阻断但记录）。

#### 5.8.3 UE 原型

- 审计与权限面板：用户管理（含邮箱字段）、角色/权限、ABAC 策略、委托权限点配置、email 连接器配置（SMTP/IMAP）。

#### 5.8.4 业务逻辑

- **视角**：业务系统
- 复用 multi-tenant 权限引擎（evaluatePermission：super_admin→RBAC→ABAC→默认拒绝，5min TTL 缓存，BUG-011 已修复）+ mtStore 隔离。补 ConnectorType.email（当前枚举无 email），email 连接器基础收发经 SMTP/IMAP/API。委托权限点模型参考钉钉 OAuth scope 自研。

#### 5.8.5 数据描述

- 输入：用户/角色/权限点、邮箱配置、租户上下文（HMAC）。
- 流转：权限评估（RBAC/ABAC）→ 委托权限存储（mtStore）→ email 收发（连接器）→ 审计日志（关键操作 100%）。
- 输出：生效权限、邮件收发结果、审计条目。

#### 5.8.6 验收标准 AC

- **正常路径**：
  - Given 管理员分配角色+委托权限，When 用户登录操作，Then 系统按 RBAC+ABAC 放行授权范围、拒绝越权。
  - Given email 连接器已配置，When 发送/接收邮件，Then 系统成功收发并归档。
  - Given 关键操作（权限变更/邮件发送），When 执行，Then 100% 写审计日志（N2）。
- **异常路径**：
  - Given 用户尝试无权限操作，When 触发，Then 系统拒绝并写安全审计事件，不泄露数据。
  - Given SMTP 配置错误，When 发邮件，Then 系统提示连接失败并建议检查配置，不丢邮件队列。
  - Given HMAC 默认硬编码密钥，When 启动，Then 系统告警建议配置并持续记录（安全加固）。

#### 5.8.7 外部集成接口

- 依赖邮箱服务（SMTP/IMAP 或 Exchange），同步接入（F11）；复用 multi-tenant 权限引擎（进程内）。钉钉/飞书连接器为 Out-of-Scope 预留（O3/D0 §3）。

### 5.9 US-9 HR 真实计算（F12 简化规则引擎 MVP；F13 完整规则引擎完整版）

- **异常路径**：
  - Given 考勤/基数缺失，When 计算，Then 系统提示缺字段并阻止，不输出错误值。
  - Given 规则配置冲突，When 保存，Then 系统提示冲突并建议修正。

#### 5.9.7 外部集成接口

### 5.10 US-10 多租户客户端隔离与 100% 审计（F14 MVP；F15 服务端强隔离完整版）

#### 5.10.2 业务流程

  - **正常路径**：Given 用户在租户 T1 操作，When 执行任意关键操作（权限变更/组盘/客服/HR 计算），Then 系统写审计日志带 TenantID/UserID/时间戳，且 T1 数据经 mtStore 命名空间与其他租户隔离。
  - **异常路径**：Given 越权尝试跨租户访问，When 触发，Then 系统拒绝（filterByTenant 行级过滤）并写安全事件。

#### 5.10.4 业务逻辑

- 复用 mtStore（tenantKey=`tenant:${tid}:${key}` 强制注入 TenantID）+ auditLogger（writeAuditLog/recordSecurityEvent/generateAuditReport/exportAuditReport）+ fileIsolation（SHA256/水印/目录隔离）。MVP 客户端模拟隔离（明确边界，不引入后端）；完整版（F15）Node+PostgreSQL 行级/库级隔离（U-03 方案A）。

#### 5.10.5 数据描述

- 输入：关键操作事件、租户上下文（HMAC）、用户标识。
- 流转：操作 → 审计日志（TenantID/UserID/时间/动作/结果）→ 存储（mtStore/IndexedDB）→ 导出报表；数据按 tenantId 目录隔离。
- 输出：审计日志、安全事件、合规报表。

#### 5.10.6 验收标准 AC

- **正常路径**：
  - Given 任意关键操作，When 执行，Then 系统 100% 写审计（含租户/用户/时间/动作，单条写入小于 50ms 不阻塞主流程，待上线实测校准，见 §6.2），且可在审计面板查询导出（N2）。
  - Given MVP 客户端隔离，When 同机多租户切换，Then 各租户数据经 mtStore 命名空间隔离，互不越权。
- **异常路径**：
  - Given 跨租户访问尝试，When 触发，Then 系统拒绝并写安全事件（R-03 缓解）。
  - Given 审计导出超限，When 导出，Then 系统分页/滚动导出（rotateOldEntries），不丢数据。

#### 5.10.7 外部集成接口

- 复用 multi-tenant 模块（进程内）；告警经 AlertChannel（含 email，见 US-8）。完整版服务端强隔离依赖自建后端（F15/O2）。

### 6.4 安全性需求

> 满足相关安全标准（等保三级审计可追溯雏形、100% 原创 IP 合规）。

#### 6.4.1 安全密码设置

- 产品若涉及账号密码设置功能，需要支持达到以下设置强度：**8 位以上大小写字母 + 数字 + 特殊字符**。MVP 账号体系复用现有 RBAC+ABAC，若新增本地账号密码须满足此强度；管理员密钥（VORZAI_MT_HMAC_SECRET）须由用户配置，禁止使用默认硬编码密钥（启动告警）。

#### 6.4.2 安全软件架构

- 应保证自身结构中各模块的通信安全：moduleBus 事件总线、LLM 适配器、file-io 均进程内调用，无跨进程明文暴露。
- 应保证组件、用户、资源的认证与访问控制：RBAC+ABAC 引擎（super_admin→RBAC→ABAC→默认拒绝），5min TTL 缓存，行级过滤（filterByTenant/filterByDepartment）。
- 当应用系统存在与外部其他应用系统进行交互时，应保证应用系统与外系统接口的安全：email 连接器（SMTP/IMAP/API）使用加密传输（TLS）；真实平台 API（完整版）使用 HTTPS + 密钥管理；限制外部可获取内容，使用安全通讯协议。

#### 6.4.3 安全设计

- 应提供认证授权功能：登录态 + 租户上下文（HMAC-SHA256 签名/校验，generateToken/verifyToken JWT 形态模拟）+ 委托权限模型（参考钉钉 OAuth scope 自研）。

#### 6.4.4 安全开发

- 应对函数入口参数的合法性和准确性进行检查：工具调用/Skill 执行前校验 slot 与权限。
- 应进行输入边界检查，限制输入的正确长度和格式：文件上传类型白名单 + 5MB 分片 + 病毒扫描（可疑扩展名拦截）；对话输入长度限制。
- 应保证不因代码的编写导致出现可被直接利用的高危漏洞：避免注入（LLM 提示注入缓解，参考 Rasa CALM 抗注入设计）。
- 应在应用系统输入输出模块中进行适当的过滤，以防范恶意指令和内部信息泄露：对话输出过滤、文件水印（applyWatermark）、租户数据隔离。
- 禁止使用未经授权和验证的代码：100% 原创自研，不复制 Dify/钉钉/飞书/北森代码（O3/R-01）。
- 应保证应用程序不存在任何可绕行安全机制的行为或遗留后门：审计 100% 覆盖关键操作，默认拒绝越权。

#### 6.4.5 安全测试和部署

- 应进行安全扫描测试：第三方 IP 合规自查（许可证声明补全，G5/U-04）、代码扫描。
- 应进行安全配置基线检查：HMAC 密钥配置、CSP、权限默认拒绝。
- 应进行安全功能的测试：RBAC+ABAC 越权用例、审计覆盖率 100% 验证。
- 系统在上线前应不存在高危风险：G3 自动校验 + G4 人工审核 + 安全设计（security-architect）确认。

#### 6.4.6 数据安全

- **数据存储和传输加密**：应在用户密码、身份鉴别信息等重要数据的存储、传输过程进行适当加密，保障信息不被泄露——HMAC 租户上下文签名、email/API TLS 传输、文件 SHA256 + 水印；本地数据经 mtStore 命名空间隔离。
