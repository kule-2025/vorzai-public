## 1. 安全总体架构

### 1.1 安全总体架构图

> **总览**：1 张图，叠加展示——网络分区、流量入口安全产品（fail2ban + Nginx rate limiting / ModSecurity / iptables）、主机/容器安全、Vault PKI、Teleport（堡垒机）、安全运营中心（Wazuh）、日志服务（Loki + Grafana）、审计存储。
>
> **部署形态分两态描述**：
> - `[MVP]`：无服务端安全组件，安全由 Electron CSP + contextIsolation + 用户设备系统防火墙 + 本地密钥链承担。
> - `[完整版]`：引入自建安全组件（Nginx + ModSecurity + fail2ban + iptables + Vault + Wazuh + Teleport + Loki/Grafana），详见下表。

### 1.2 威胁模型

> **总览**：采用 **STRIDE** 方法，识别并规避系统可能存在的威胁风险。
> 每条威胁必须对应到后续章节（§2~§7）的某项缓解措施，形成"**威胁—缓解措施映射表**"。
> 威胁建模基于《系统设计》中的模块边界、数据流、接口契约、身份边界、外部依赖和运行形态。

#### 1.2.1 STRIDE 威胁识别

| 威胁类别（STRIDE） | 典型示例 | 影响模块/接口 | 严重程度 |
| --- | --- | --- | --- |
| 仿冒（Spoofing） | 身份伪造、token 重放、LLM 调用伪造身份 | M7 鉴权、E-01 LLM 调用 | 高 |
| 篡改（Tampering） | 请求参数篡改、IndexedDB 数据篡改、配置文件篡改 | M1~M7 全部写入接口 | 高 |
| 否认（Repudiation） | 缺少操作审计、用户否认操作 | M7 auditLogger、关键业务操作 | 中 |
| 信息泄露（Information Disclosure） | 敏感数据暴露、密钥泄露、日志含明文 | M6 email 连接器、t_audit_log、L2~L4 数据 | 高 |
| 拒绝服务（DoS） | CC 攻击、慢查询、LLM 额度耗尽、IndexedDB 写满 | 公网入口、LLM 调用、IndexedDB | 中 |
| 权限提升（Elevation of Privilege） | 水平越权（IDOR）、垂直越权、容器逃逸 | M7 权限引擎、M1~M5 接口 | 高 |

## 2. 身份与访问管理（IAM）

### 2.1 身份认证（Authentication）

#### 2.1.1 用户登录

- **登录方式**：账号密码（主方式）+ 邮箱验证码（辅助方式）。`[MVP]` 不引入第三方社交登录；`[完整版]` 保留 OAuth 2.0 / OIDC 扩展接口。
- **图形验证强制场景**：登录、获取邮箱验证码。
- **MFA / 2FA**：管理端（角色 admin）必须开启 MFA（密码 + TOTP OTP）；`[完整版]` 控制台子账号强制 MFA。
- **风险登录检测**：异地登录（IP 地理信息变化）二次验证 + 非常用设备提示。

#### 2.1.2 密码策略（量化阈值）

| 项 | 取值 |
| --- | --- |
| 最小长度 | ≥ 8 位（业务系统）；≥ 12 位（admin 管理账号） |
| 复杂度 | 同时包含数字、大写字母、小写字母、特殊字符（可配置开关） |
| 加密传输 | 前端 RSA 加密提交，密文传输 |
| 加密存储 | bcrypt（cost factor ≥ 12）加盐哈希；**禁止 MD5 / SHA1 明文** |
| 更换周期 | 默认 90 天提醒（可配置） |
| 重复限制 | 不允许使用最近 5 次的密码 |
| 失败锁定 | 连续失败 5 次锁定 1 小时（次数和时长可配置） |
| 自动登出 | 30 分钟无操作自动登出 |
| 注册策略 | 不允许用户自行注册，仅管理员创建；改密需原密码验证 |

#### 2.1.3 会话管理

- **Token 类型**：HMAC 签名的 JWT（`[MVP]` 进程内模拟 JWT；`[完整版]` Node 服务签发标准 JWT）；**禁止 URL 携带 token**。
- **有效期**：默认有效期 24 小时（可配置），提供续期与主动注销接口。
- **互踢机制**：管理端同账号仅允许单设备登录，新登录踢掉旧会话；`[完整版]` 异地登录需提示。
- **风险登录**：异地 / 异常登录二次验证（MFA 或验证码）。

### 2.2 授权与权限控制（Authorization）

#### 2.2.1 权限模型

默认采用 **RBAC0**（用户—角色—权限），权限粒度敏感的场景叠加 **ABAC**（属性条件）。

**角色定义**（与《系统设计》§4.2 对齐）：

| 角色 | 权限范围 | 适用场景 |
| --- | --- | --- |
| admin | 全部模块读写 + 账号管理 + 权限配置 + 审计导出 | 系统管理员 |
| operator | 业务链读写 + 对话工作台 + 知识库 | 运营 / 客服一线 |
| analyst | OGSM 查看 + HR 查看 + 仪表盘 | HR / 中层管理者 |
| viewer | 只读（看板 + 知识库） | 决策者 / 访客 |

#### 2.2.2 权限维度

- **接口级**：API 网关统一鉴权 + 接口签名（HMAC-SHA256）；M7 鉴权拦截器（`JwtAuthInterceptor`）覆盖全部业务模块。
- **数据级**：行级（按 `tenant_id` + 归属人）、列级（字段脱敏）；`[MVP]` 通过 mtStore 命名空间隔离实现行级，`[完整版]` 通过 PostgreSQL 行级 `tenant_id` WHERE 强制。
- **功能级**：菜单、按钮、操作的细粒度控制（路由元信息 `meta.roles = [...]`）。

#### 2.2.3 多租户隔离

- **`[MVP]`**：**逻辑隔离（客户端模拟）**。采用 mtStore 命名空间隔离（`keyPath=tenant:${tid}:${key}`），HMAC 租户上下文强制注入，`[MOCK]` 服务端强隔离。
- **`[完整版]`**：**物理隔离（服务端强隔离）**。PostgreSQL 行级 `tenant_id` WHERE 强制注入 + 库级隔离（可选）。经中间确认 U-03 方案A 裁决。

#### 2.2.4 越权防护

- **水平越权（IDOR）**：每个查询 / 修改接口必须校验资源归属（`tenant_id` + `user_id`），返回 C403001。
- **垂直越权**：RBAC 角色校验 + 接口拦截器双层校验（`@AuditLog` + `@RequireRole`）。

### 2.3 云账号与云资源访问

> `[MVP]` 无云账号。`[完整版]` 以下设计替代云账号安全管理。

#### 2.3.1 账号策略

使用自建 Vault PKI + Teleport 管理运维账号；**禁止直接使用系统 root**，禁止为系统 root 创建访问密钥。

#### 2.3.2 权限分离

人员权限（密码 + MFA，通过 Teleport 堡垒机使用）与服务权限（Vault 动态凭据，应用调用使用）分离。

#### 2.3.3 高敏权限分离

高敏操作账号权限与低敏操作隔离；Teleport 运维通道按角色限制可访问主机。

| L4 | 高敏 | 手机号、邮箱凭证、密码、LLM API Key、Vault 令牌、AKSK | 基于 Vault 加密、强脱敏，严格审计 |

**数据分级映射表**（对齐《系统设计》数据表）：

| --- | --- | --- |

### 3.2 数据传输安全

#### 3.2.1 公网访问

全链路 "HTTPS / TLS 1.2+"，禁用 SSLv3、TLS 1.0/1.1。
- `[MVP]`：E-01/E-02 出口使用 HTTPS（上游服务商证书）；自动更新（GitHub/Gitee）使用 HTTPS。
- `[完整版]`：Nginx LB 前置 TLS 终结（TLS 1.2+，强密码套件）；Nginx 仅开放 443（HTTPS），80 强制跳转 443。

#### 3.2.2 服务内部访问

- 低敏感、进程内访问：HTTP 协议寻址访问（`[MVP]` 模块间调用）；进程内无网络传输风险。
- 高敏感、服务间访问（`[完整版]`）：**mTLS 双向证书认证**，认证服务访问身份（由 Vault PKI 引擎签发 6~12 月证书，自动轮换）。

#### 3.2.3 数据库连接

- `[MVP]`：IndexedDB 本地连接（无网络传输风险）。
- `[完整版]`：PostgreSQL **SSL 连接（TLS 1.2+）**；Redis 连接启用 ACL 认证。

#### 3.2.4 接口签名

- **算法**：HMAC-SHA256 防篡改 + nonce（防重放）+ timestamp（时间窗口 ±5min）。
- **签名范围**：method + URI + body + nonce + timestamp。
- **防重放**：nonce 在服务端 5 分钟内去重（`[MVP]` IndexedDB 去重表；`[完整版]` Redis 去重键 TTL 5min）。
- **`[MVP]` 适用**：进程内模块调用使用 HMAC 租户上下文签名；`[完整版]` Node 服务 REST API 使用标准 HMAC-SHA256。

#### 3.2.5 传参禁忌

- **禁止 URL 携带**：token、AKSK、手机号、邮箱密码、LLM API Key 等敏感信息。
- **禁止 GET 请求体**：敏感参数必须走 POST 请求体 + TLS 加密。
- **禁止日志打印**：敏感参数（`password` / `token` / `apiKey` / `phone`）不得写入业务日志。

### 3.3 数据存储安全

#### 3.3.1 加密存储（仅敏感数据需要）

- **对称加密**：AES-256-GCM（业务侧大数据量）。
- **非对称加密**：RSA-2048（密钥交换、签名）。
- **`[MVP]` 落盘加密**：本地 IndexedDB 存储，通过操作系统级文件加密（BitLocker/FILEVault）提供物理层保护；L4 数据（LLM API Key）额外通过本地密钥链（keychain/keytar）加密存储。
- **`[完整版]` 落盘加密**：
  - PostgreSQL：透明数据加密（TDE，通过文件系统层 LUKS 或 Vault 客户端加密 CSE）。
  - MinIO：服务端加密 SSE-S3（AES-256），密钥由 Vault 托管。
- **密钥管理**：`[完整版]` Vault（vault-vorzai-prod）托管，**禁止硬编码到代码或配置文件**。

#### 3.3.2 敏感字段单向哈希加盐

- 用户密码：bcrypt（cost factor ≥ 12）加盐哈希，不可逆。
- Token 摘要：SHA-256 + 随机盐，用于对账，不存储明文。

#### 3.3.3 数据库安全

- `[MVP]`：IndexedDB 对象仓库，本地进程内访问，无网络暴露风险；慢查询通过 IndexedDB 事务超时控制。
- `[完整版]`：
  - 账号最小权限；**禁止业务直连 PostgreSQL superuser**；运维使用单独只读账号。
  - 开启慢查询日志（pg_stat_statements，阈值 100ms）、审计日志。
  - 启用 SSL 连接、备份加密（pg_dump + GPG）。
  - PostgreSQL 主从流复制（`[完整版]` 跨 AZ）。

#### 3.3.4 文件存储安全

- `[MVP]`：本地文件通过 Electron fs 访问；上传文件类型校验（魔数 + 扩展名 + 大小限制）。
- `[完整版]` MinIO：
  - 启用服务端加密（SSE-S3）。
  - 私有桶 + 预签名 URL（短有效期 ≤ 15min）。
  - 防盗链（Referer 校验）。
  - 上传文件病毒扫描 / 类型校验（魔数 + 扩展名 + 大小 ≤ 100MB）。

#### 3.3.5 数据使用安全

- **展示脱敏**：手机号 `138****8888`；邮箱 `j***@example.com`；HR 薪酬仅查看者本人可见。
- **数据导出管控**：导出审批流 + 水印（操作人 + 时间）+ 行数限制 + 操作审计。
- **数据销毁**：逻辑删除 + 定期物理销毁（≥ 90 天）；明确过期数据清理策略。

#### 3.3.6 数据备份与异地容灾

| 存储类型 | `[MVP]` 备份策略 | `[完整版]` 备份策略 |
| --- | --- | --- |
| IndexedDB / PostgreSQL | 全量导出（本地文件 / MinIO）；90 天滚动 | 周期性备份，跨 AZ 备份至 MinIO |
| Redis | 不适用（MVP 无 Redis） | RDB + AOF，按 RPO 选择性跨 AZ |
| MinIO / 重要数据 | 本地备份导出 | 版本控制开启，跨区域复制（自建） |

#### 3.3.7 隐私合规

- **个人信息保护**：《个人信息保护法》、《数据安全法》。
- **用户同意机制**：隐私政策 + 用户明示同意；数据最小化采集；可被遗忘权（数据删除请求处理流程）。
- **数据出境**：`[MVP]` 数据全部在用户设备本地，无出境；`[完整版]` 数据在自建服务器本地，无云出境。

## 4. 应用安全

> 以 OWASP Top 10 为典型风险场景，结合本系统业务特点设计。

### 4.1 输入安全

| 风险 | 防护措施 |
| --- | --- |
| SQL 注入 | 强制参数化查询（TypeORM 参数绑定 / PostgreSQL `pg.format`）；动态字段（order by / group by）使用模板白名单校验；`[MVP]` IndexedDB 查询通过 ORM 封装，无原生 SQL |
| XSS | 输出编码（React 默认 HTML 转义）；Electron CSP（script-src 'self', frame-src 'none', form-action 'self'）；Cookie HttpOnly + Secure；服务端响应头 Content-Security-Policy |
| CSRF | 所有写接口要求 HMAC 签名（含 timestamp + nonce）；`SameSite=Strict`；关键操作（组盘提交/客服工单/薪酬计算）二次验证 |
| 命令注入 | 系统禁用动态命令执行；`[MVP]` Electron 主进程禁用 `child_process.exec`（安全沙箱） |
| 反序列化 | 禁用危险反序列化（fastjson autoType、Jackson @class）；JSON 解析仅使用标准 JSON.parse |
| SSRF | 禁用本机 LLM/邮箱出口以外的网络请求；`[完整版]` Node 服务 URL 白名单 + 内网 IP 黑名单（10.x/172.16-31.x/192.168.x） |
| 文件上传 | 类型校验（魔数检测）+ 扩展名白名单（pdf/csv/txt/md/docx/xlsx）+ 大小限制（≤ 100MB）+ 随机重命名 + `[完整版]` MinIO 隔离桶 |
| XXE | 禁用 XML 外部实体解析（DTD）；默认不使用 XML 格式 |
| 开放重定向 | 跳转 URL 白名单（仅允许应用内路由 + 已知安全域名） |
| 业务逻辑注入 | 关键业务参数（grouping price、salary、margin）服务端范围校验 + 异常值检测 |

### 4.2 输出安全

#### 4.2.1 统一异常处理

错误码及信息提示（参考《系统设计》§3.5.1），**禁止暴露堆栈、SQL、内部路径**。所有异常统一包装为 `Result` 结构（code + msg + traceId + timestamp）。

#### 4.2.2 调试信息

调试信息（debug、stacktrace、环境配置）严禁出现在生产环境响应中。开发环境通过环境变量控制。

### 4.3 业务逻辑安全

#### 4.3.1 越权防护

- **水平越权（IDOR）**：每个查询 / 修改接口必须校验资源归属（`tenant_id` + `user_id`）；M7 鉴权拦截器自动注入 tenantId。
- **垂直越权**：RBAC + 接口拦截器双层校验；admin 专属接口（账号管理、权限配置、审计导出）需 `@RequireRole('admin')`。

#### 4.3.2 防刷防爬

- 限流：IP / 用户 / 接口三维度（参考《系统设计》§3.5.3）。
- `[完整版]` Nginx rate limiting（全局 1000 QPS / 单租户 200 QPS / 单用户 LLM 5 QPS）。
- 滑动验证码：登录、邮件发送接口图形验证码。

#### 4.3.3 防薅羊毛

- 风控规则：LLM 调用频次限制（单用户 5 QPS）；组盘创建频次限制（单用户 10 次/天）。
- 黑名单：IP 黑名单 + 用户黑名单（通过 Teleport 运维配置）。
- 行为分析：`[完整版]` Wazuh 异常行为检测（高频访问、异常操作模式）。

#### 4.3.4 幂等性

- 防重复提交：前端 token + 后端唯一键（`biz_req_no` / `X-Idempotency-Key`）。
- 幂等键生命周期：`[MVP]` IndexedDB 去重表保留 7 天；`[完整版]` Redis 去重键 TTL 24h。

#### 4.3.5 关键业务二次验证

- 薪酬计算、组盘提交、批量导出、密钥变更、账号禁用等操作需二次验证（密码确认 / MFA）。
- `[完整版]` 邮件发送（外发）需审批 + 发送记录审计。

### 4.4 第三方与供应链安全

- **第三方组件漏洞扫描**：npm audit（CI 强制门禁，高危阻断）；`[完整版]` Trivy 镜像漏洞扫描（高危阻断）。
- **开源协议合规审查**：所有 npm 依赖检查许可证（GPL / AGPL 商业风险审查）；100% 原创约束，禁止复制闭源代码。
- **第三方服务接入安全评估**：E-01 LLM（数据传输 / API 合规 / 数据驻留）；E-02 邮箱（TLS + 合规）；E-03 电商平台（密钥 + 合规）。
- **供应商安全管理**：LLM 服务商合同含数据保护与审计条款；定期复评。
- **镜像源管理**：npm 使用官方 registry（registry.npmjs.org）+ 内网镜像备份；`[完整版]` Docker 镜像使用私有仓库（自建）。

## 5. 网络与基础设施安全

> `[MVP]` 无服务端网络拓扑，网络形态完全依托用户设备本地网络栈 + 操作系统防火墙。本节以 `[完整版]` 为权威，同时标注 `[MVP]` 等价本地形态。

### 5.1 网络分区

- 区分 **DMZ**（对外暴露，Nginx LB）、**业务区**（int / uat / prod 隔离，Node 服务）、**DevOps 区**（CI/CD / 运维，Teleport 堡垒机），避免网络渗透。
- 网段不重叠；容器网段与业务网段不冲突。
- 限制生产区与公网的访问通路：仅通过 Nginx LB（仅 443 入站）出入公网；`[完整版]` iptables NAT 控制出站。

**`[完整版]` 网络分区清单**（对齐《部署设计》§2.2.3）：

| 网络区域 | CIDR 范围（示例） | 用途 | 对外暴露 |
| --- | --- | --- | --- |
| DMZ | 10.10.1.0/24 | Nginx LB + ModSecurity + fail2ban | 公网（仅 443） |
| 业务区 INT | 10.10.2.0/24 | Node 服务（int 环境） | 不暴露 |
| 业务区 PROD | 10.10.3.0/24 | Node 服务（prod 环境） | 不暴露 |
| DevOps | 10.10.4.0/24 | Teleport + Wazuh + Vault + Prometheus/Grafana | 不暴露（仅 Teleport 堡垒机 SSH） |
| 数据区 | 10.10.5.0/24 | PostgreSQL + Redis + MinIO | 不暴露（仅业务区访问） |

> **说明**：CIDR 范围为安全侧建议值，实际网络划分由 platform-architect 按部署环境确定；安全组 / iptables 规则由 security-architect 定义（权威方）。

### 5.2 流量管控（南北向 + 东西向）

#### 5.2.1 公网入口防护（`[完整版]`）

- **DDoS 防护**：fail2ban + Nginx rate limiting（自建），替代云 DDoS 高防。
  - fail2ban 规则：`maxretry=5, bantime=3600`（5 次失败封禁 1h）；`maxretry=10, bantime=86400`（10 次失败封禁 24h）。
  - Nginx rate limiting：`limit_req_zone $binary_remote_addr zone=global:10m rate=100r/s`；超出返回 429。
- **WAF**：ModSecurity（Nginx 模块）+ OWASP CRS v3.4 规则集（替代云 WAF）。
  - 规则集：OWASP CRS v3.4（SQLi + XSS + RFI + LFI + RCE + Session Fixation）。
  - 自定义规则：CC 防护（单 IP 500 请求/分钟限制）+ 黑白名单（运营维护）+ 数据脱敏（响应拦截手机号/身份证）。
  - 运行模式：Detection（初始）→ Blocking（稳定后 30 天）；每日规则更新。
- **Nginx LB**：仅暴露 443（HTTPS），80 强制跳转 443；TLS 1.2+（强密码套件 ECDHE-RSA-AES256-GCM-SHA384）。

#### 5.2.2 网络边界防护（`[完整版]`）

- **iptables / nftables**（替代云防火墙）：互联网边界墙 + NAT 边界墙 + 入侵防御（Wazuh 规则联动）。
  - 默认策略：`DROP`（入站默认拒绝）。
  - 显式放通：DMZ 仅 443 入站；业务区仅 DMZ 来源 8080 入站；DevOps 区仅 Teleport 来源 SSH 入站。
  - NAT 边界：iptables NAT 控制出站（固定出口 IP，对接 E-01/E-02/E-03）。
  - **禁止 0.0.0.0/0 开放**：22/23/3306/6379/5432 等敏感端口。

#### 5.2.3 主机流量防护（`[完整版]`）

- **iptables ACL**：默认拒绝 + 显式放通（替代云安全组）。
  - DMZ 安全策略：入站仅 443（80 强制跳转）。
  - 业务区安全策略：入站仅 DMZ 来源 8080（Nginx API Gateway）。
  - DevOps 安全策略：入站仅 Teleport 来源 22（SSH）。
  - 数据区安全策略：入站仅业务区来源 5432/6379。

#### 5.2.4 运维通道防护（`[完整版]`）

- **Teleport**（替代云堡垒机）：
  - SSH 密钥登录（禁止密码登录）。
  - 会话录像（全量录制，保留 ≥ 180 天）。
  - 文件传输审计（SCP/SFTP 操作记录）。
  - 操作回放（历史操作可追溯）。
  - 仅限运维管理域访问（角色限制）。

### 5.3 主机与容器安全

#### 5.3.1 主机安全

- 最小化安装、关闭非必要服务、定期补丁。
- 账号管控：**严禁 root 远程登录**，运维通过 Teleport 使用独立账号。
- 登录方式：**SSH 密钥登录（密钥对）**，禁止密码登录。
- 安装 **Wazuh**（替代云主机安全组件）：漏洞扫描、恶意文件检测、文件完整性监控（FIM）、密码破解阻断。

#### 5.3.2 容器 / K8s 安全（`[完整版]`）

- 如使用容器化部署：RBAC 最小化、NetworkPolicy 隔离命名空间、Pod 安全策略。
- 容器镜像扫描（Trivy，漏洞 + 敏感信息）；`[MVP]` 无容器。
- 异常进程监控、容器逃逸检测、K8s API 异常请求监控（Wazuh 规则）。
- **不在镜像中打包密钥**；通过 Vault 运行时动态下发。
- 禁止特权容器、高权限容器。

### 5.4 中间件安全

#### 5.4.1 网络隔离

仅业务区内的应用层可访问；**禁止公网暴露**。PostgreSQL（5432）、Redis（6379）、MinIO（9000）仅业务区可达。

#### 5.4.2 强制鉴权

- PostgreSQL：启用密码认证 + SSL；修改默认账号。
- Redis：启用 ACL（`requirepass`）；禁止默认空密码。
- MinIO：启用访问密钥 + SSE-S3 加密。

#### 5.4.3 审计

- 启用 PostgreSQL 审计插件（pg_audit）、慢查询日志（pg_stat_statements）。
- Redis 启用命令日志（`[完整版]` 可选）。
- MinIO 启用访问日志（audit trail）。

## 6. 密钥与凭证管理

> **`[完整版]` 核心变化**：所有密钥统一由 HashiCorp Vault（vault-vorzai-prod，自建）管理，替代云 KMS。

### 6.1 密钥分级与存储

| 密钥类型 | 存储 / 管理方式 | 轮换周期 |
| --- | --- | --- |
| 数据库密码（PostgreSQL / Redis） | Vault 动态凭据（`[完整版]`）；`[MVP]` 本地密钥链 | 7 天（临时凭证动态获取，≤ 1h 自动过期） |
| 云 AKSK（MinIO 访问密钥） | Vault secrets engine（`[完整版]`）；`[MVP]` 本地密钥链 | 30 天 |
| 服务间通信密钥（mTLS） | Vault PKI 引擎（`vault-vorzai-prod`，`[完整版]`）签发客户端证书 | 6~12 月（自动轮换） |
| 用户密码 | bcrypt 加盐哈希（不可逆，不入库明文） | 不适用（不可逆哈希） |
| API Key / Token（LLM 平台 / 第三方） | Vault secrets engine（`[完整版]`）；`[MVP]` 本地密钥链 | 90 天 |

**Vault PKI 引擎配置（`vault-vorzai-prod`）**：

| 用途 | 证书类型 | 有效期 | 签发 CA |
| --- | --- | --- | --- |
| mTLS 客户端证书 | leaf cert | 6~12 月（自动轮换） | Vault PKI CA |
| 服务端 TLS 证书 | leaf cert | 6 月（自动轮换） | Vault PKI CA |
| 内部 CA 签发 | intermediate CA | 12 月 | Vault PKI Root CA |

### 6.2 AKSK 泄露防护

#### 6.2.1 方案 A：Vault 动态凭据

- 数据库密码：通过 Vault PostgreSQL secrets engine 动态生成（≤ 1h 自动过期），应用通过 Vault Agent 自动注入。
- MinIO AKSK：通过 Vault 定期自动轮换，应用动态获取。

#### 6.2.2 方案 B：Vault 策略限制

- 通过 Vault ACL 策略限制密钥访问范围：按服务 / 环境 / 用户隔离。
- Vault 访问日志（audit log）记录每次密钥获取，用于审计追溯。

### 6.3 密钥使用红线

- **严禁** AKSK / 数据库密码 / Token 出现在源码、Git 仓库、前端代码、日志、错误堆栈、URL、配置明文。
- **禁止**多业务共用同一对 AKSK；按业务 / 环境隔离签发（Vault 策略限制）。
- 上线前必须通过代码扫描（trufflehog / git-secrets，CI 红线拦截）+ 镜像扫描（Trivy），识别硬编码密钥。
- 密钥一旦疑似泄露，立即在 Vault 控制台禁用并轮换；事后排查 Vault 审计日志确认影响面。
- 每一对密钥明确所有人、用途、存储位置、轮换日期；**上线 checklist 中包含"密钥扫描通过"项**。

### 6.4 `[MVP]` 密钥管理

- 密钥存储：本地密钥链（keychain / keytar）。
- LLM API Key：存储在本地密钥链，运行时无需硬编码。
- HMAC 密钥（mtStore 租户签名）：`[MVP]` 使用环境变量 `VORZAI_MT_HMAC_SECRET`（由管理员首次安装时设置，不在代码中默认值）。
- 邮箱凭证：存储在本地密钥链。

## 7. 运行时安全：监控、审计、应急

### 7.1 安全事件监控

- **入侵检测（IDS / IPS）**：Wazuh（`[完整版]` 自建，开源 SIEM + IDS）+ Nginx + ModSecurity 攻击日志。
- **敏感操作**：数据导出、批量删除、密钥变更、用户角色变更、薪酬计算。
- **登录异常**：异地登录、连续失败、夜间登录、非常用设备。
- **权限异常**：越权请求、敏感接口高频调用、非常规权限提升。
- **监控数据流**（`[完整版]`）：
  ```
  Node 服务 / PostgreSQL / Redis ──┬─► Metrics ──► Prometheus ──► Grafana
                                   ├─► Logs    ──► Promtail ──► Loki ──► Grafana
                                   ├─► Traces  ──► OpenTelemetry ──► Grafana
                                   └─► Audit   ──► 独立审计存储（≥ 180 天）
  ```

### 7.2 审计日志

**审计 5 维度**（与《部署设计》§7.3 对齐）：

| 审计维度 | `[MVP]` 实现 | `[MVP]` 保留期 | `[完整版]` 实现 | `[完整版]` 保留期 | 审计字段 |
| --- | --- | --- | --- | --- | --- |
| 业务操作审计 | 本地 IndexedDB（t_audit_log，独立存储） | ≥ 90 天（本地滚动） | 独立审计库（PostgreSQL）+ 独立审计桶（MinIO） | ≥ 180 天 | 操作时间、来源应用、来源类型、来源 IP、操作者、事件名称、读写类型、扩展字段 |
| 数据库操作审计 | 经 M7 权限切面记录（IndexedDB 操作留痕） | ≥ 90 天 | PostgreSQL pg_audit 插件 + 独立审计库 | ≥ 180 天 | SQL、执行人、客户端 IP、时间、影响行数 |
| 云资源审计 | 不适用（无云资源） | — | 自建基础设施变更审计（Wazuh 配置变更 + Vault 操作日志 + Teleport 会话） | ≥ 180 天 | 事件名称、时间、事件源、源 IP、请求 ID、操作者 |
| 堡垒机审计 | 不适用（无远程运维） | — | Teleport 会话录像 + 操作回放 + 文件传输日志 | ≥ 180 天 | 主机、数据库运维日志、文件传输日志 |
| WAF / 防火墙审计 | 不适用（无公网 WAF） | — | ModSecurity 攻击日志 + iptables 日志 + Nginx 访问日志（经 Promtail → Loki） | ≥ 180 天 | 攻击日志、访问日志、拦截记录 |

**审计日志安全要求**：
- **不可篡改**：审计日志独立存储（`[MVP]` IndexedDB 独立对象仓库；`[完整版]` 独立审计库 + MinIO 审计桶，与业务存储物理隔离）。
- **独立存储**：与业务数据分离，防止业务数据篡改连带审计被篡改。
- **灾备演练**：≥ 1 次/年。

### 7.3 应急响应

- **应急预案**：漏洞响应、数据泄露、被攻击、密钥泄露、勒索病毒（5 类）。
- **备份与恢复**：明确 RPO / RTO（`[MVP]` RPO ≤ 60min / RTO ≤ 30min；`[完整版]` RPO ≤ 5min / RTO ≤ 15min）；**每年 ≥ 1 次灾备演练**。
- **应急 Runbook**：`[完整版]` Runbook 索引（对齐《部署设计》§6.2.1 RB-07~RB-11）：
  - RB-07：服务端错误率升高 → 降级/回滚
  - RB-08：PostgreSQL 主库不可用 → 主备切换
  - RB-09：Redis 哨兵切换异常 → Redis 恢复
  - RB-10：MinIO 写入失败 → 对象存储恢复
  - RB-11：安全事件（越权/爆破/密钥泄露）→ 安全事件响应
- **应急联系**：
  - `[MVP]`：联系自建运维团队（@运维 on-call）。
  - `[完整版]`：联系自建运维团队（@SRE on-call + @安全 on-call）。
  - 所有应急 Runbook 中"联系云厂商"替换为"联系自建运维"。
